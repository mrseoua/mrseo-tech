## Стратегия интента
- Не направлять общий высокочастотный запрос «разработка интернет магазина» на узкую страницу **приложения**: это каннибализация с уже существующей услугой создания магазина.
- Для «парсинг сайтов» важнее вопросы разрешённого сбора, форматов и обновления данных. Не обещать обход технических ограничений.
- Для платежей: оплата обрабатывается провайдером, сайт не обязан хранить платёжные данные.
- Для PWA и мобильных приложений: показывать ограничения платформ, не обещать обязательную публикацию в магазинах приложений.
- Интеграция и корпоративная автоматизация — отдельные задачи; не дублировать общую страницу разработки ПО.
- В каждой из 7 страниц: собственные Title/Description/H1, три проблемы, три действия, результат, три FAQ, две внутренние ссылки; родитель `/ru/web-development/` с семью иллюстрированными ссылками. Главная, UA-копирайт и остальные 18 языков не меняются.

## Статус SEO и публикации
- Новые `/ru/<slug>/` — настоящие WordPress virtual routes с собственными каноникалами.
- Ровно две реальные языковые версии (UA `uk-UA` + RU `ru`) получают взаимные `hreflang` через существующий SEO-реестр, без создания фиктивных альтернатив.
- Сохранить **global noindex,nofollow + X-Robots-Tag**. Пока сайт закрыт от индексации, эти страницы **не могут начать ранжироваться**. Открытие индексации — отдельное решение владельца после готовности сайта.
- Снимки CI — изолированный WordPress, они не доказывают попадание на production. Не объединять PR до QA и согласования публикации.
